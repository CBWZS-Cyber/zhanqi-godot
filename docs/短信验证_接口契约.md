# 短信验证通道 · 接口契约（2026-10-09）

> 背景：用户要求「登录的邮箱验证改成短信验证，**邮箱验证算是备选方**」。
> 范围：**注册** + **找回密码**（登录本身是昵称+密码，无验证码，不动）。
> 服务端**已上线**（`/opt/zhanqi-cloud/server.js` md5 `518cd702…`，`sms.js` `88ba333b…`）。
> **客户端也已上线**（10.5.3，2026-10-09 晚）—— 两端都完成，见第三节。
> ⚠️ 本文是**接口契约**；服务端行为以代码为准，客户端实现以 `cloud_api.gd` / `main_ui.gd` 为准。

## 一、设计总纲

| 项 | 规定 |
|---|---|
| 通道选择 | 请求里带 `channel`：`"sms"` 或 `"email"` |
| **`channel` 缺省** | **= 老行为（邮箱）** —— 已发布客户端不传该字段，语义必须逐字节不变 |
| 手机号唯一 | 一个手机号只能绑一个账号（否则"按手机号找回"有歧义） |
| 未绑手机号 | 找回密码走短信通道时回 `masked:""`（与"昵称不存在"同一形状，**故意不区分**，防枚举） |
| 验证码归属 | 短信码由**阿里云生成与校验**（一次性消费）；服务端**不存短信码** |
| 手机号可见性 | 回给本人的 `account.phone` 只有**掩码**（`182****0225`）；完整号码只留服务端 |

## 二、接口

### 1. `POST /send-code` —— 发验证码

| 用途 | 请求体 | 成功响应 |
|---|---|---|
| 注册 · 短信 | `{channel:"sms", phone}` | `{ok, channel:"sms", masked:"182****0225", ttl:300, resendAfter:60}` |
| 注册 · 邮箱（老路） | `{email}` | `{ok, ttl:300, resendAfter:60}`（**无 channel 字段**） |
| 找回 · 短信 | `{channel:"sms", name, purpose:"reset"}` | 同上（`masked` 为该账号**自己绑定的**号） |
| 找回 · 邮箱（老路） | `{name, purpose:"reset"}` | `{ok, masked:"c***n@qq.com", ttl, resendAfter}` |

- 手机号格式错 → `400`；触发限流 → `429`（`error` 是中文，含"请 N 秒后再试"）。
- 找回时账号未绑手机号 → **`200` 且 `masked:""`**（不是错误码！客户端据此提示"该账号没绑手机号，改用邮箱"）。

### 2. `POST /register`

```jsonc
// 短信：code 为短信验证码
{ "channel": "sms", "name": "...", "pass": "...", "phone": "13800000001", "code": "246810" }
// 邮箱（老路，`channel` 可省略）
{ "name": "...", "pass": "...", "email": "a@b.com", "code": "123456" }
```

- 成功 `201` + `{token, account}`；昵称被占 `409`；手机号已被绑 `409`；验证码错/过期 `400`。
- 号码带 `+86` / 空格 / 横线会被归一，客户端**尽量规范化后再发**。

### 3. `POST /reset-password`

```jsonc
{ "channel": "sms", "name": "...", "code": "246810", "newpass": "..." }
{ "name": "...", "code": "123456", "newpass": "..." }   // 邮箱老路
```

成功 `200` + `{token, account}`（**成功后即已登录**，无需再输密码）。

### 4. `POST /bind-phone` —— 老账号补绑手机号（**需登录**）

| action | 请求体 | 说明 |
|---|---|---|
| `send` | `{action:"send", phone}` | 发绑定码（模板 `100004`） |
| `commit`（缺省） | `{action:"commit", phone, code}` | 验码并写入；`account.phoneBound` 变 `true` |

- 未带 token → `401`；号码已绑**别人**账号 → `409`。

## 三、客户端改造清单（**已完成**，2026-10-09）

| 文件 | 实际做法 |
|---|---|
| `scripts/net/cloud_api.gd` | 新增 6 个方法：`register_sms` / `send_code_sms` / `send_reset_code_sms` / `reset_password_sms` / `bind_phone_send` / `bind_phone_commit`，加 `bind_phone_done` 信号与 `CH_SMS` 常量。**刻意做成"不同渠道调不同方法"而不是给一个 `channel` 默认参数** —— 服务端缺省是邮箱，靠默认值会"以为发短信、其实发邮件"，这种错极难查 |
| `scripts/ui/main_ui.gd` | 注册/找回面板各加**两个横排小按钮**「短信验证 / 邮箱验证」（`ButtonGroup` 互斥，选中态用 `●`/`○` 前缀标出）；`_login_email` 改名 `_login_contact`（按渠道是手机号**或**邮箱）；切渠道**清空已填内容**；找回面板**发码后锁渠道**；新增 `_make_channel_btn` / `_looks_like_phone` / `_norm_phone` |
| `tests/cloud_auth_smoke.gd` | 新增 **G 段**（双通道界面 + 本地校验 + 源码契约断言）；另加 `_detach_cloud()` 防回归真发信 |
| `tests/_probes/sms_channel_probe.gd` + `fake_sms.js` | **请求形状探针**：打到本地假云端、把收到的 JSON 读回来断言（不是读源码猜） |

> ⚠️ 一条**回归红线**：`cloud_auth_smoke.gd` 里凡是会走 `_on_forgot_send()` / `_on_cloud_register()`
> 的动作，都必须先 `_detach_cloud(ui)` —— 否则会真的打到线上（原先每次跑回归给账号绑定的
> 邮箱**发一封重置邮件**；加了短信渠道后会**真发短信，每条计费**）。

## 四、成本与限流（服务端已实现，客户端别绕）

短信**每条计费**（套餐 1000 次，至 2027-10-10）：同号 60 秒重发 / 5 条每日；同 IP 10 条每小时 / 20 条每日；
**全局日上限 200**。客户端必须把 `429` 的 `error` **原样展示**（它是给人看的中文），不要自己编文案。

## 五、回归红线

老客户端（已发布 10.5.x）**只发** `{email}` / `{name,pass,email,code}` / `{name,purpose:"reset"}` —— 这些路径
必须继续可用。新参数一律**显式传入**，绝不依赖服务端默认值的变化。

> 另见 `docs/忘记密码_接口契约.md`（邮箱路径的原始契约，仍然有效）。
